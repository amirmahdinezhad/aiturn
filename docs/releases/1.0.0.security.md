# Security review for Aiturn 1.0.0

Reviewed on 2026-11-06. Scope: complete application/repository identity rename,
fresh 1.0.0 version line, cleanup, documentation and the owner-requested removal of focus outlines. The existing updater signing
public key is preserved. Credentials and private signing files are outside source.

## Results

- TypeScript and production frontend build passed.
- Vitest: 37 files, 355 tests passed. Release/security/reset harness: 13 tests passed.
- Rust: offline locked check passed; 205 library tests and 8 integration tests passed; 3 live-account tests remain intentionally ignored.
- `pnpm run security:check` passed: no JavaScript advisories, no Gitleaks source/history leaks, production CSP/IPC/updater policy tests passed, and the resolved dependency union for aarch64/x86_64 macOS passed RustSec with warnings denied.
- Scanners: cargo-audit 0.22.2; Gitleaks 8.30.1; a freshly fetched RustSec database containing 1,409 advisories. Re-run the gate after candidate changes and immediately before publication.
- The full cross-platform lockfile also contains unsupported-target findings: zip 4.6.1 (RUSTSEC-2026-0429, 0367, 0368, 0369); unmaintained proc-macro-error, zbus_names, zvariant and zvariant_derive; glib RUSTSEC-2024-0429; and yanked async-executor 1.14.0. These packages are absent from the supported macOS dependency union. Windows/Linux releases are not approved by this review.
- The owner requested complete removal of focus outlines, superseding the earlier thin-focus fix. All authored focus edges and focus-only input border changes were removed, and browser-default outlines are suppressed. Chromium/WebKit Tab checks passed in dark/light at 430×600 with normal/reduced motion; pointer and content-panel checks passed. TypeScript, all 37 Vitest files / 355 tests, production build and the mechanical design detector passed again. The running native WebKit client received a fresh CSS HMR update on port 5174. This follow-up used browser evaluation and native HMR verification; the earlier 1px native samples no longer describe the current design. No temporary probe remains in source.
- Native dev panel loaded the preserved workspace and saved Codex accounts at localhost:5174 with provider usage. Browser preview showed the expected missing-IPC state. Served Settings source contains the new preference namespace. With preview moved to about:blank, an established native WebKit connection received a fresh Settings HMR update.
- Universal app and DMG build passed. `release:verify` confirmed the reviewed bilingual notes, archive checksums, both arm64/x86_64 slices, strict ad-hoc code signature, DMG integrity and updater signature. An altered archive was rejected. Bundle identifier, executable and version are the new Aiturn values, and the release executable contains no previous product name. The mounted DMG was visually inspected in Finder.
- Repository-wide source search found no remaining previous product name. Local QA captures, old reports, credentials and build output are excluded from public commits.

## Remaining verification

Publication is withheld at the owner's request. The staged universal signed package passed `release:verify`; the approved
publication command repeats artifact verification and the security gate on the
clean tagged candidate. Public feed/download and Settings → Updates server
verification remain deferred until publication is explicitly authorized.

The macOS bundle is ad-hoc signed and not Apple notarized. A new bundle identity
and restarted version line require a manual install from earlier development
versions and reimport of saved accounts into the renamed profile store. Existing
provider logins are not deleted by the source cleanup. This machine’s app-owned
profile folders were copied to the new names to preserve its current workspace.

Fresh external browser sign-ins, real account switching/reset redemption and an
installed-app upgrade are not exercised in this cleanup; unit/integration tests
cover their relevant boundaries, without claiming live-provider equivalence.
The computer-use tool could not reliably inspect the hidden tray Settings
window, although the owner opened it and native panel/HMR/focus evidence was
recorded. Complete the native Settings → Updates check against the public feed after the
owner authorizes publication. Until that release exists, the new feed has no
published 1.0.0 update to download. Passing checks are bounded evidence and do not
prove absence of bugs or vulnerabilities.
